# 对抗式架构评审 — ARCHITECTURE-SPINE (2026-09-08)

## 0. 方法与立场

评审对象是 AD-1～AD-11 这套"架构脊柱"。攻击方法：对每个洞构造**两个下一层单元**（两个不同的 Epic/包团队，下称 α 与 β），各自的设计**逐条满足全部 AD 的字面与可合理解释**，两者拼装后系统级失败（违反某条 INV/NFR/FR/AC，或同一平台出现两种互斥行为）。每找到一个这样的构造，即证明脊柱存在一个"合规但不可拼装"的洞，需要新 AD 或收紧现有 AD。

合规证明格式：每个单元列出其设计**触及**的 AD 及合规理由；未列出的 AD 视为无接触面（该单元不依赖其约束），这本身也是合规。引用原文均出自 ARCHITECTURE-SPINE.md；PRD/蓝图引用用于说明系统级后果与文本依据。

**总判定：找到 8 个洞（H1–H8）。其中 H2 属于最硬的一类——AD-11 原文明确枚举了两个都合法的行为；H1/H3/H4/H5/H7 属于适用域/谓词未定义类；H6 属于两条 AD 相互冲突类；H8 属于术语未分类类。合计需要 2 条新 AD、6 处收紧。**

## 2. H1 — 同一实体两个 owner：WorldModel 的双事件族

**文本依据**：蓝图 §17.2 事件表**同时**存在 `claim.proposed/accepted/refuted/...` 与 `world_model.drafted/validated/activated/suspended/scope_narrowed/retired/revoked/...` 两族；PRD §3 词汇表把 WorldModel 列入"认知资产"（"Claim、核验器、策略包、技能、WorldModel、提示"）；蓝图 §11.1 认知类型表含"World Model"行；但 PRD FR-020 的九类认知（Working…Policy）**不含** WorldModel。两份上游文档各自支持一种归属，脊柱没有裁决。

**α = E2 认知团队**：WorldModel 是认知资产 → 其生命周期是 Claim 生命周期的子集 → 全部状态变更走 `claim.*` 事件（claim.proposed=candidate、claim.accepted=active、claim.refuted=revoked、缩小范围=claim 修订事件）。

- 合规证明：AD-2 ✓（一切状态变更=追加 claim.* 事件，修正=claim.refuted 新事件不改旧记录）；AD-1 ✓（只依赖 protocols）；AD-7 ✓（Claim 实体带 tenant_id/project_id）；AD-9 ✓（claim schema 带 semver）。**α 根本不写任何 world_model.* 事件——没有任何 AD 要求某族事件必须被某个包使用。**

**β = E5 模型实验室团队**：AD-6 要求"模型从 candidate 到 active 必须携带验证轨迹……元决策 Event 留痕"——验证轨迹与元决策需要模型自己的谱系与状态机 → 用 `world_model.*` 事件族承载 candidate→shadow→active→suspended。

- 合规证明：AD-2 ✓（追加式）；AD-3 ✓（验证轨迹 Artifact 先落盘、哈希校验后才被 world_model.activated 引用）；AD-6 ✓（无轨迹不激活）；AD-5/AD-11 ✓（回放/性质测试确定性）；AD-1 ✓（只依赖 protocols 与更底层核心包 ST）。

**拼装失败**：同一个 WorldModel 实例存在两条互不知晓的事件流和两个"当前状态"投影。当反例到达：α 发 `claim.refuted` 并按 FR-024 传播失效依赖 Plan；β 的投影仍是 active——没有任何一方会发 `world_model.suspended`（β 不消费 claim 事件，α 不认识 world_model 事件族）。规划器（β 域，FR-043 的"激活要求覆盖当前动作与范围匹配"检查读 β 的投影）继续用已被推翻的模型仿真。AC-04 要求"偏差注入中旧计划 100% 失效、不继续批量执行"——系统级失败，而两单元各自的测试全绿。AD-2 的"因果父项"在两流之间也没有桥接事件可指。

**修复**：新 AD（实体唯一 owner）：protocols 中登记"实体类型 → 唯一 owner 包 + 唯一权威事件族"注册表；跨族联动只能由 owner 发桥接事件；并显式裁决 WorldModel 归属（建议归 E5，world_model.* 为权威，cognition 只存引用与依赖边）。

## 3. H2 — 幂等的两种"合法"行为 + 键派生函数未定义

**文本依据**：AD-11 原文："动作执行携带幂等键，**重复请求返回原执行结果或明确拒绝**"——AD 自己枚举了两个互斥且都合法的行为。且 AD-5 要求重放/Eval 确定性 → 幂等键不能含随机数（否则历史不可重放）→ 键必须是确定性纯函数——但函数与作用域均未定义。

**α = E4 可信执行团队（Tool Gateway）**：实现"重复 → 返回原执行结果"；幂等键作用域 = 网关全局（跨 Run），键 = sha256(tool + 参数指纹)。

- 合规证明：AD-11 ✓（选择了明文枚举的第一种行为）；AD-4 ✓（网关唯一通道、唯一持凭证）；AD-5 ✓（键派生不含熵）；AD-10 ✓（async-first）。

**β = E6 评测团队**：六组消融（FR-064）要求重跑历史任务。按 AD-5 确定性，同一配置派生出与历史 Run **相同的幂等键**。β 依赖网关在此上下文"明确拒绝"重复键，以向评测报告证明动作没有真实再执行（否则消融测的是缓存命中）。

- 合规证明：AD-11 ✓（选择第二种行为）；AD-5 ✓（确定性派生）；AD-2/AD-9 ✓。

**拼装失败**：α 的网关在评测时直接返回历史 Execution → 消融与成本统计（SM-4、AC-07）全部失真且**以合规的方式失真**。走出困境的三条路各有一方违约：β 加随机盐 → 违反 AD-5（不可重放）；α 改为拒绝 → 破坏生产重试语义（FR-004 恢复后重试、FR-006 重试）；α 按 Run 作用域记忆结果 → 键作用域语义仍未定义，换一个团队又会分叉。这是一个**无合规出口**的留白。

**修复**：收紧 AD-11：(1) 幂等键的派生函数与作用域由 protocols 唯一定义（建议 key = f(tenant_id, run_id, contract_hash, attempt_no)，attempt_no 显式计入重试序号使键确定性且跨 run 不撞）；(2) 把两种行为按场景钉死——同一 run_id 内重复 = 返回原结果；跨 run_id 重复 = 明确拒绝；重放/评测上下文一律接确定性替身（承接 AD-5），替身返回"原结果引用"而非重新执行。

## 4. H3 — 投影折叠语义各自实现（检索索引 vs 权威投影）

**文本依据**：AD-2"当前状态一律由投影从事件流重建"、AD-11"任意投影可从事件历史重建"——都只约束投影的**可重建性**，不约束折叠**语义**的唯一性。AD-1 的依赖图里 COG 与 ST 互不依赖，两者各自经 protocols 的 EventSource 端口读同一事件流完全合法。

**α = E1 存储团队**：FR-013 要求按业务实体检索 → 为 Claim 建"当前状态"派生索引，fold 规则 = 按 Run 内单调序号取**最后一次状态类事件**（proposed/supported/accepted/disputed/refuted/retired）。

- 合规证明：AD-2 ✓（读侧纯投影、不写事实）；AD-7 ✓（索引查询经 tenant 过滤）；AD-11 ✓（checkpoint + 可从历史重建）；AD-1 ✓（不 import cognition，只经端口）。

**β = E2 认知团队**：权威 Claim 投影实现 FR-022/024 的完整语义：`scope_narrowed` 不是终态而是"状态回退 + 范围收窄后仍 accepted"；`refuted` 触发依赖传播失效。

- 合规证明：同上四条 ✓。

**拼装失败**：一条 accepted Claim 收到缩小范围事件：β 投影 = accepted（新范围内）；α 索引的 fold 不认识该事件类型（或按普通状态事件处理）→ 仍按旧范围全域 accepted。FR-013 的检索跳转出与认知面矛盾的视图；若 Context Builder（FR-025）读 α 的索引，就向模型装配了已收窄范围外的过期主张。注意：新事件类型算不算 AD-9 的"minor（只增可选字段）"也未定义——这个子留白并入 H7。

**修复**：收紧 AD-2/AD-11：每个实体类型的 canonical 状态折叠函数随 schema 一起定义在 protocols，单一实现、所有读者复用；派生索引不得自带语义 fold，只能物化 canonical fold 的输出，或显式标注"非权威缓存 + 过期容忍声明"。

## 5. H4 — 租户作用域在 CAS 去重与删除证明上的缝隙

**文本依据**：AD-7"**每个持久实体**自带 tenant_id + project_id"——CAS blob 与向量 embedding 行是不是"持久实体"未定义；AD-3 + 蓝图 §10.5"相同内容哈希去重，但租户计费和权限仍独立"要求全局内容寻址与去重；FR-017 要求删除留下"不含内容的证明事件"。

**α = E1 存储团队**：blob = 纯内容，全局去重（AD-3 单一 sharded 布局），blob 本身不带 tenant_id——α 的读法是"blob 不是实体，引用它的 Artifact 元数据行才是实体（带 tenant_id，AD-7 ✓）"。

- 合规证明：AD-3 ✓；AD-7 ✓（按其读法）；AD-11 ✓（CAS 写入天然幂等）。

**β = E2 派生 worker + 向量索引**：embedding 行 = DerivedAsset 实体，带 tenant_id（AD-7 ✓），向量索引按 (tenant_id, content_hash) 建键。worker 幂等按 AD-11"同内容哈希先查后算"：租户 B 请求派生 → 查到租户 A 的同内容 embedding 已存在 → 跳过计算。

- 合规证明：AD-7 ✓、AD-11 ✓、AD-2 ✓（派生=新事件）。

**拼装失败（三条，任取其一都成立）**：

1. 若 β 为省存储把"先查"做在**全局**向量索引上（只存一份向量）→ 索引行 tenant_id=A → B 的查询被 AD-7 强制的作用域过滤挡住 → B 检索不到自己刚请求派生的资产（静默漏检）；
2. 若 β 放宽过滤以命中去重行 → 跨租户访问，NFR-003"跨租户访问数=0"被系统级破坏，而两个单元各自都合规；
3. 删除分叉：租户 A 请求删除（FR-017）→ α-A 实现"blob 仍被 B 引用则保留、对本租户出删除证明"→ **删除证明与字节存活矛盾**（审计语义造假）；α-B 实现"直接删 blob"→ B 的 DerivedAsset 悬空（AD-3 只禁止事件悬空引用，未覆盖派生物引用）。

**修复**：新 AD（CAS 租户语义）：(1) blob 定义为非实体但必须维护**每租户引用计数**；(2) 删除 = 本租户 tombstone + 计数递减，计数归零才物理清除；删除证明事件必须区分"本租户逻辑删除"与"内容物理清除"两种谓词；(3) 派生去重键默认含 tenant_id，跨租户复用仅限显式白名单（呼应蓝图 §11.5 禁止跨客户迁移）。

## 6. H5 — 只读动作旁路六段链（沙箱接口 × Tool Gateway 凭证边界）

**文本依据**：AD-4"**状态改变型**动作只能经 Contract → Policy →（Approval）→ Tool Gateway → Execute → Verify 管道……Tool Gateway 是唯一持有**业务工具**凭证的组件"——(a) 只读动作完全在约束域外；(b) EnvironmentAdapter 不是"业务工具"，其执行不在网关垄断范围内；(c) FR-032 工具清单的风险/幂等/副作用是**自声明**的，无 AD 校验声明真实性。

**α = E5 模型实验室团队**：FR-048"现实执行逐步核验"需要环境探测 → 沙箱内规划器发起探测动作（observe / navigate），直连 EnvironmentAdapter 端口（protocols 定义）。α 判定探测为只读（其 GUI Pack 的工具清单自声明 navigate=read-only）。

- 合规证明：AD-1 ✓（lab 依赖 protocols 端口）；AD-4 ✓（非状态改变型，不在管道适用域内；EnvironmentAdapter 也非业务工具）；AD-6 ✓（沙箱内运行、无凭证无网络——环境端口调用由沙箱外代理转发）；AD-5 ✓。

**β = E4 可信执行团队**：同一动作（navigate / refresh）在其风险注册中 = 会话状态改变（R1）→ 必须走完整六段管道，产生 contracted/policy/execution/verification 事件。

- 合规证明：AD-4 ✓；AD-11 ✓（幂等键）；AD-2 ✓（每段留事件）。

**拼装失败**：α 路径的动作不产生六段链事件 → NFR-001（链完整率 100%）与 AC-01（完整回放）系统级失败；且同一 GUI Pack 从两个入口进入时行为不同（一边要契约一边不要），同一个 Run 的时间线（FR-060）出现无因果父项可追的动作。**没有任何 AD 被违反**——因为管道的适用域由"是否状态改变"界定，而该界定又由清单自声明，清单说谎不在任何 AD 的检查范围内。

**修复**：收紧 AD-4：(1) 经适配器的一切环境/工具动作（含只读）至少产生最小 action 事件（动作、参数摘要、结果 artifact 引用）纳入事件流；(2) 动作的读写分类由平台统一注册表裁定，工具清单自声明只能上调风险不能下调；(3) EnvironmentAdapter 的执行也必须经网关代理或显式的只读旁路端口（该端口仍写事件）。

## 7. H6 — 时钟二难：AD-5 注入时钟 vs AD-6 墙钟硬限制

**文本依据**：AD-5"非模型代码路径不得直接使用系统时间……一律经 RunContext 注入（时钟、种子、配置快照）"；AD-6"CPU/内存/进程/**时间**硬限制"。两条规定在"沙箱超时如何实施"上正面冲突，且"非模型代码路径"没有判定谓词。

**α = E5 团队（读法一）**：沙箱 supervisor 用 RunContext 注入的时钟实施墙钟硬限制。

- 合规证明：AD-5 ✓（不读系统时间）；AD-6 ✓（有硬限制）。

**β = E5 团队（读法二，或另一支实现同一功能的团队）**：沙箱执行的是**不可信生成代码** → 沙箱属于"模型路径"（类比"模型调用的请求与响应整体作为 Artifact 落盘，重放时不重新调用"）→ supervisor 读真实墙钟、把真实耗时作为事件落盘。

- 合规证明：AD-5 ✓（按其读法，沙箱非"非模型代码路径"）；AD-6 ✓；AD-2 ✓（耗时入事件）。

**拼装失败**：α 的读法下，重放时虚拟时钟冻结/匀速推进 → 超时永不触发 → **生产中因超时而安全停止并导出复现包的 Run（FR-004），在离线重放中"成功完成"**——AC-08（复现包在干净环境可离线重放）与 NFR-002 系统级失效。β 的读法下行为正确，但其 supervisor 是平台代码读墙钟，按 AD-5 字面违约。两个团队互相指责且都有文本支持。附带同型分叉：cross-model 核验器（核验器组合件之一）在 α=模型路径（请求响应落 artifact、重放不重调）在 β=确定性代码路径（需注入种子）→ 同一核验器两处归类不同，重放行为不同。

**修复**：收紧 AD-5：(1) 定义"模型路径"谓词 = **输出不是其已记录输入的纯函数的一切调用**（含 cross-model 核验器），一律落 artifact；(2) 时钟二分——**决策时钟**（注入 RunContext、进重放）与**资源限制时钟**（真实墙钟、以事件落盘、重放时按事件恢复而非重测），AD-6 的墙钟限制明确归后者。

## 8. H7 — 可选字段缺失语义分叉（AD-9 的 N-1 窗口陷阱）

**文本依据**：AD-9"minor 只增可选字段；……保 N-1 客户端兼容窗口"——只规定了**生产者**可以加可选字段，没有规定**消费者**如何解释缺失。

**α = E0 协议团队**：v1.1 minor 给 `action.executed` 增加可选字段 `verification_ref`。

- 合规证明：AD-9 ✓（minor 只增可选字段）；AD-1 ✓（schema 定义在 protocols）。

**β₁ = E1 检索投影**：读到缺失 → 解释为"该动作无核验要求"（历史原因），索引标 N/A。**β₂ = E6 消融统计**：读到缺失 → 解释为"核验尚未发生"，计入 pending 并进入失败分类。

- 合规证明（两者相同）：AD-9 ✓（事件通过 schema 校验，消费合法）；AD-2/AD-11 ✓（投影各自重建）。

**拼装失败**：同一段历史事件流被读出两个核验率；N-1 窗口内新旧读者并存时，同一个查询（"这个 Run 有多少动作未经核验？"）返回两个都"合规"的答案。回放时间线（FR-060）与消融报告（FR-064）互相矛盾。另一个子洞：新增**事件类型**（如 H3 的 scope_narrowed）算不算 minor？"只增可选字段"按字面不含新事件类型，但没有任何条文明说，两团队必然分叉。

**修复**：收紧 AD-9：(1) 每个可选字段必须携带规范缺省语义（缺失 = 唯一确定值），消费者不得对缺失分叉行为，需要区分时必须新增显式字段而非利用缺失；(2) 明文规定新事件类型不属于 minor，只能主版本或进 minor 白名单枚举。

## 9. H8 — 审批载荷 vs 控制面零载荷（AD-8 术语未分类）

**文本依据**：AD-8"控制面组件……只接收元数据、签名摘要与去标识聚合指标，任何原始 Artifact 载荷与**原始证据内容**不得进入控制面"；蓝图 §16.1 把 Approval Service 放在控制面；FR-034 要求批准"绑定具体动作、参数、范围、时限"——批准者必须**看见**参数。

**α = E9 控制面团队（Hybrid 部署）**：审批路由在控制面，按 AD-8 只收元数据与摘要 → 审批界面呈现参数哈希与脱敏摘要 → 批准者**盲批**。

- 合规证明：AD-8 ✓（逐字遵守）；AD-7 ✓（租户隔离）；AD-9 ✓。

**β = E4/E3 数据面团队**：审批会话的参数原文由数据面代理渲染给批准人，理由：动作参数是"元数据"，不是"原始 Artifact 载荷"，也不必然是"原始证据内容"。

- 合规证明：AD-8 ✓（按其读法，参数不在禁入清单内）；AD-4 ✓（Approval 在管道内）；AD-2 ✓。

**拼装失败**：同一平台两种部署对同一条审批记录产生不同语义（盲批 vs 明批）。而"参数是否属于原始证据内容"确实无定义——写动作参数常直接摘自原始观察（GUI 文本框内容、OCR 结果），α 与 β 的读法各有文本依据。后果：SM-C2（不必要审批/审批地狱）与 UJ-2（审批者看得懂才批）不可同时满足；审计导出（FR-068）对"批准时批准者看到了什么"无法给出一致答案。

**修复**：收紧 AD-8：定义三级数据分类——治理元数据（控制面可存）/ 动作参数（数据面持有，按需投递到审批会话，不落控制面存储）/ 原始载荷与证据内容（仅数据面）；控制面只保存审批决定与参数摘要引用。

## 10. 裁决汇总：对脊柱的修改建议

**新增 2 条 AD**：

- **AD-12（实体唯一 owner）**：每个持久实体类型在 vasta-protocols 登记"唯一 owner 包 + 唯一权威事件族 + canonical 状态折叠函数"；跨族联动只能经 owner 发出的桥接事件；其余投影只能物化 canonical fold 输出或显式声明非权威缓存。（合并 H1/H3 的修复。）
- **AD-13（CAS 租户语义）**：blob 为非实体内容，必须维护每租户引用计数；删除区分"本租户逻辑删除（tombstone）"与"内容物理清除"两种证明谓词；派生去重键默认含 tenant_id，跨租户复用需显式白名单。（H4 的修复。）

**收紧 6 处现有 AD**：

- AD-11：幂等键派生函数与作用域唯一化（f(tenant_id, run_id, contract_hash, attempt_no)）；"返回原结果"限定同一 run_id 内，跨 run 一律拒绝；评测/重放上下文接确定性替身。（H2）
- AD-4：一切动作（含只读）入事件记录；读写分类由平台注册表裁定，清单自声明只能升不能降；EnvironmentAdapter 纳入网关代理或只读旁路端口。（H5）
- AD-5：定义"模型路径"判定谓词；决策时钟（注入）与资源限制时钟（真实墙钟、入事件、重放按事件恢复）二分。（H6）
- AD-9：可选字段必须带规范缺省语义、禁止消费端对缺失分叉；新事件类型不属于 minor。（H7）
- AD-8：三级数据分类（治理元数据 / 动作参数 / 原始载荷）与审批载荷的数据面归属。（H8）
- AD-7（措辞补充）：明确"持久实体"清单包含 DerivedAsset、向量索引行、checkpoint 与派生索引条目，不包含 CAS blob（其租户语义移交 AD-13）。（H4 的配套）

**与既有 gap 记录的关系**：脊柱 memlog 已记录的开放项（首批模型适配器、DSL 边界、沙箱生产化时间点）均为"尚未决策"类；本评审发现的 8 个洞是"已决策文本内部的分叉空间"类，两类互补，上表修改不影响已记录的 Deferred 清单。

## 11. 评审边界
