# 产品简报：VastaCore

> 本简报用于内部对齐定位、范围与成功标准；深度依据见 [addendum.md](./addendum.md)。[[ASSUMPTION] 口径为内部产品对齐文档——若用于融资或对外叙事，"问题"与"成功标准"两节需按受众重写。]

## 执行摘要

VastaCore 是面向长程、多模态、工具调用型 Agent 的**认知与执行可靠性平台**：保留原始证据、管理可修订认知、约束并核验行动、按需构建可执行世界模型，并把每次成功与失败沉淀为可测试资产。它要解决的问题不是"Agent 不够聪明"，而是"Agent 的认知过程不可复现、不可审计、不可恢复"。

这个问题正处在研究成熟与产品空白的交汇点：VISTA、Tycho、Schema、AVO 等项目已在公开基准上证明"证据保留 + 可验证世界模型"这类 Harness 工程能大幅提升通用模型的可信任务完成率，但现有三类方案（Computer-Use Agent、Memory 中间件、治理平台）都没有覆盖 Agent 的认知层。VastaCore 以开放核心 SDK + 运行时 + 证据认知 + 世界模型实验室 + 控制治理的平台组合切入，以 GUI/Computer Use 为首个商业楔子，按 L0 观察 → L4 自适应自治的五级渐进路径交付。[[ASSUMPTION] 商业叙事定位为"生产 Agent 可靠性平台"（plan.md §28.1），而非研究复现项目。]

## 问题

企业 Agent 落地的真实卡点不在模型智能，而在三件事（详见 plan.md §1、§2）：

1. **排障不可复现**。Agent 失败后只剩压缩过的日志和摘要，无法回到"当时看到了什么、为什么这么决策"。长程任务一个失败要人翻几小时日志。
2. **行动不可核验**。带副作用的动作（下单、改数据、发邮件）执行前没有预期声明，执行后没有读回对账，错误被发现时往往已经造成真实成本。
3. **认知不可积累**。每会话从零开始；好不容易归纳出的规则、反例、技能随上下文消失，错误认知还会被静默继承和放大。

现有方案各有缺口：Computer-Use Agent 依赖 DOM/结构化输入、跨任务失忆；Memory 中间件（Mem0 类）语义摘要 + 向量检索，原始高保真证据永久丢失；企业治理平台管 SSO/审计/灰度，但对"Agent 是否可靠理解了它的环境"完全不涉及。

## 解决方案

给 Agent 的观察、认知、行动、验证、学习装上完整工程闭环：

- **无损证据库**：原始截图/视频/工具响应内容寻址存档，摘要和抽取只是索引层，任何时候可回到像素级原始证据。
- **认知资产化**：每条理解都是带证据、反例、置信度、版本和生命周期的主张（Claim），可晋升、可推翻、可撤回，错误认知不会静默污染。
- **行动契约（Action Contract）**：每个有副作用的动作执行前声明预期变化与不变量，执行后独立核验（读回、视觉 Diff、不变量规则）；出现偏差时，依赖该动作的计划即失效，并进入有界恢复。
- **按需世界模型**：只在高价值机制上把经验蒸馏成可执行、可回放验证的局部模型（Tycho 启发），是否建模由元控制器按收益决策，而不是默认全建。
- **回放与评测**：任何失败 Run 可导出最小复现包，转为回归任务，形成认知资产 CI/CD。

采用路径从 L0 Observe-only（只记录不干预）开始，按"环境 × 工具 × 操作 × 数据范围"逐格授予自治权；产品入口是调试回放与排障工具，再进契约执行和企业治理。

## 差异化

1. **证据不早熟压缩**——与所有"检索前先摘要/向量化"的商业记忆方案方向相反（VISTA 验证过的机制，见"解决方案"）。
2. **认知资产生命周期**——证据、规则、反例、核验器、技能、局部模型全部版本化、可测试、可回滚，形成别家没有的复利资产。
3. **按需建模的元决策**——是否程序化建模本身是受治理的收益决策（Tycho 实证：按需委派优于始终/从不建模），既不过早结构化，也不让语言推理停留在不可验证。
4. **渐进自治的信任模型**——自治权凭可验证表现动态升降，天然对接企业审批与合规，而非一次性放权。
5. **诚实的边界**——公开基准只用于研究校准，产品价值由私有变体、影子运行和生产指标证明；不承诺完整数字孪生，高风险操作默认禁止。

壁垒最终不在代码而在数据飞轮：跨模型/环境的可靠性数据、失败到回归资产的闭环、经验证的领域核验器，以及客户积累的私有认知资产。

## 目标用户

- **Agent 开发者**（首要楔子）：已有 PoC 或编排能力，被"失败查不出原因"折磨，需要可回放证据链和调试工具。成功 = 失败定位时间从小时级降到分钟级。
- **AI 平台工程师**：需要统一运行面、预算、模型路由和恢复，而非每团队自造。
- **领域专家/安全治理**：用业务语言定义不变量和禁区，审批与审计有据可查。
- **理想客户画像**：工作流超 10 步、错误有真实成本、已有模型/编排团队但缺排障核验治理，愿意提供失败轨迹或影子环境。[[ASSUMPTION] A5（plan.md §38.2）：付费意愿待验证，Stage 0 需 20–30 个访谈确认。]

## 成功标准

- **北极星**：在既定风险和成本预算下完成且可验证的 Agent 任务数。
- **技术 MVP 验收**（Stage 1 进入门，全表见 plan.md §32）：40+ 任务完整回放；100% 写动作具备前后证据 + 契约 + 核验链；偏差注入下旧计划 100% 失效；六组消融中完整系统（Full）相对基线（Baseline）稳定净收益。
- **商业验证**：设计伙伴失败定位时间从小时级降至分钟级；至少一个客户从 L0/L1 升到 L2 Enforce；试点转付费。
- **护栏**：token/存储/延迟成本与误阻断率控制在预算阈值内；隐私与越权事件为零。

## 范围

**首个版本（Foundation MVP，单机）包含**：Python SDK + Local Runtime；SQLite 元数据 + 内容寻址证据库；分层记忆与主张图初版；Action Contract + 基础策略/核验 + 计划失效；规则 DSL 局部世界模型 + 历史回放 + 沙箱；HTML Replay；六组消融评测。

**商业形态**（默认方案，待 Developer Preview 前确认，见 addendum §8）：本地 Replay/调试免费开源，Contract/Policy 与企业治理收费，land-and-expand。

**明确不做**：不训练基础模型；不替代 LangGraph/编排器/RPA/对象存储/IAM；不建完整数字孪生；不默认放开高风险自治；早期不建公开插件市场、不自研消息队列和向量库；GUI/视频/游戏/工业垂直包按门槛逐个进入（GUI 优先，Stage 2 起步）。

[[ASSUMPTION] MVP 范围取 plan.md Stage 1（2–5 个月）交付物；路线图整体 0–36 个月，Stage 0 验证起步 + 六个交付阶段，由证据门而非日期驱动。]

## 愿景

如果成功，VastaCore 成为生产 Agent 的"认知可靠性标准层"：任何有外部行动能力的 Agent 都能回答并证明"我看到了什么、为什么相信、准备做什么、实际发生了什么、学到的规则在哪些范围内有效、人类如何收回控制"。2–3 年内形成开放协议（观察事件、行动契约、认知资产、世界模型清单）+ 可信扩展生态 + 至少三个成熟垂直方案包，让 Agent 的认知过程从一次性上下文变成有版本、有测试、有权限的工程资产。
