## 1. 愿景

VastaCore 是面向长程、多模态、工具调用型 Agent 的**认知与执行可靠性平台**：保留原始证据、管理可修订认知、约束并核验行动、按需构建可执行世界模型，并把每次成功与失败沉淀为可测试资产。它把 Agent 的认知过程从不可复现的上下文与日志，转化为有来源、有版本、有测试、有权限、有生命周期的工程资产。用户由此获得三种此前不存在的能力：失败后十分钟内回到"当时看到了什么、为什么这么决策"；每个带副作用的动作有预期声明与独立核验；归纳出的规则、反例与技能跨会话积累且错误可撤回。

成熟形态由七个产品面构成（Open Core SDK、Runtime 数据面、证据认知面、世界模型实验室、控制治理面、回放评测、扩展生态），以 GUI/Computer Use 为首个商业楔子，按 L0 观察 → L4 自适应自治的五级渐进路径交付。长期壁垒不在代码而在数据飞轮：跨模型/环境的可靠性数据、失败到回归资产的闭环、经验证的领域核验器，以及客户积累的私有认知资产。完整问题定义与差异化论证见产品简报。

**为什么是现在**：VISTA/Tycho/Schema/AVO 一线研究已在公开基准上证明"证据保留 + 可验证世界模型"的 Harness 工程具有显著杠杆（事实边界：仅证明杠杆作用，不构成商业价值证明），但尚无产品把它做进企业可用的平台层；而企业侧 Agent 试点大量卡在排障、核验与治理三件事上。研究成熟度与产品空白的窗口期，就是现在。[[ASSUMPTION] 市场判断沿用简报，其原始数据（投产率等）未独立验证（蓝图 §2.3 边界）]

## 2. 目标用户

### 2.1 待完成任务（JTBD）

- **功能**：失败 Run 十分钟内定位首个偏差（而非翻几小时日志）；写动作执行前有预期、执行后有读回对账；规则/反例/技能跨会话可复用；高风险动作有参数级审批留痕。
- **情感**：对放权给 Agent 不再焦虑——知道它在哪一步会停、错了能收回；排障不再是无证据的猜测。
- **社会**：向审计、合规、上级证明"Agent 为什么这么做"；团队共享评测与知识而非各自维护。
- **情境**：遗留系统无 API 文档、界面随版本变化、任务跨多页面多工具异步推进——这些最难的环境正是价值最大处。

**理想客户画像**（Stage 0 筛选设计伙伴的准绳）：工作流超过 10 步、涉及多页面/多工具/异步状态；错误有真实成本，需要审计或人工批准；已有模型/编排能力但缺排障、核验与治理；愿意提供历史失败轨迹或影子环境。

### 2.2 非用户（v1）

- 只需要单轮问答、无外部副作用的聊天机器人团队；
- 寻找"一键全自动数字员工"、拒绝渐进自治与人工审批的组织；
- 需要训练自有基础模型或纯模型评测榜单刷分的团队；
- 安全关键设备实时控制场景（Embodied Pack 是长期项且有硬边界）。

### 2.3 关键用户旅程

**UJ-1. 陈默十分钟定位昨晚下单 Agent 的首个偏差。**[[ASSUMPTION] 人物与场景为推断示例]
- **人物 + 情境**：陈默，电商公司 Agent 平台工程师，维护跨 ERP/审批系统的下单流程 Agent。
- **入口状态**：昨晚的批量 Run 失败告警；本地已装 VastaCore，Run 全程 L0 记录。
- **路径**：`vasta inspect RUN_ID` 打开回放 → 时间线按因果排序 → 一键跳转"首个偏差" → 并排看动作前后原始截图与工具响应 → 发现二次确认弹窗未被处理导致重复提交。
- **高潮**：偏差点前后证据、当时生效的契约与策略同屏可见——不需要再猜。
- **解决**：一键导出最小复现包并转为回归任务；给该表单加"弹窗检测"核验器。次日同类失败在执行时被拦截。
- **边界情况**：若失败由外部系统当晚变更引起，回放显示"外部变化"事件类型，陈默直接转人工流程而非改 Agent。

**UJ-2. 财务运营专家周琳用业务语言给 Agent 划禁区。**[[ASSUMPTION] 人物与场景为推断示例]
- **人物 + 情境**：周琳，财务运营专家，不写代码，但最懂"什么操作绝对不能错"。
- **入口状态**：团队已接入 VastaCore，Domain Studio 中已有历史 Run。
- **路径**：表单式定义业务对象与状态字段 → 声明不变量（"金额与币种核对后才能提交"）与禁区（"超过阈值必须双人批准"）→ 在历史 Run 上标注正确/异常变化 → 审核系统提出的规则晋升。
- **高潮**：她定义的不变量在新 Run 上真实拦截了一次错误提交，且她看得懂拦截理由。
- **解决**：规则进入影子期 → 灰度生效；她的领域知识成为可版本、可回滚的资产。
- **边界情况**：若历史 Run 数量不足以验证不变量，先以人工标注的小样本起步，影子期相应延长。

**UJ-3. 审计员老郑导出一次事故的签名证据包。**[[ASSUMPTION] 人物与场景为推断示例]
- **人物 + 情境**：安全与合规审计员，需要就某次误操作向监管说明全过程。
- **入口状态**：只有只读审计权限。
- **路径**：按用户/时间/工具定位 Run → 查看动作前后原始证据与哈希 → 核对当时生效的模型、提示、策略与批准记录 → 导出签名证据包与最小复现包。
- **高潮**：每个结论都能回链到不可篡改的原始证据——审计报告第一次不是"信不信 LLM 的转述"。
- **解决**：事故沉淀为评测任务与策略变更，影响链可查询。
- **边界情况**：若目标证据已过保留期被删除，导出包注明缺口并附删除证明事件。

## 3. 词汇表

*下游工作流与读者必须逐字使用以下术语；全文不得引入同义词。*

- **租户/项目** — 治理与隔离边界；租户含区域、策略、密钥、配额。
- **AgentDefinition** — 可部署的 Agent 定义：模型、提示、工具、记忆及其版本。
- **Environment** — 运行环境声明：类型、版本、能力、风险。
- **Run** — 一次完整运行与可重置单元，含任务、状态、预算、配置快照。
- **Episode** — Run 内可重置的局段（如游戏关卡式重置）。
- **Event** — 追加式事实：类型、单调序号、因果父项、时间、签名。事件不可原地修改。
- **Observation** — 环境观察，分决策/过渡/终局/重置/外部五种事件类型。
- **Artifact** — 原始载荷：URI、内容哈希、MIME、分类、保留策略。内容寻址，不可变。
- **DerivedAsset** — 派生物（OCR/摘要/状态/embedding），必须可回链源 Artifact、变换与版本。
- **Claim（主张）** — 认知图节点：范围、陈述、证据、反例、依赖、置信度、状态、版本谱系。
- **Plan/PlanStep** — 可失效计划：目标、动作、依赖、状态。
- **ActionContract（行动契约）** — 写动作的前置、预期变化、不变量、成功/失败条件、核验器、超时、幂等键、补偿。
- **Execution** — 实际动作执行：请求、响应、凭证范围、副作用标识。
- **Verification（核验）** — 动作对账结果：pass / deviation / inconclusive / system_error。
- **核验器** — 执行核验的组合件（schema、读回、不变量、视觉 Diff、时序、语义、交叉模型、人工）。
- **Approval（批准）** — 绑定具体动作、参数、范围、时限、批准者的授权记录。
- **WorldModel（世界模型）** — 明确范围内环境状态/动作/观察/目标的可执行或可计算假设；生命周期 candidate→shadow→active→suspended→retired/revoked。
- **Meta Controller** — 决定直接推理/探测/建模/修复/绕过/停止的元决策组件。
- **Supervisor** — 管理预算、循环检测、检查点、故障分类与升级的组件。
- **Tool Gateway** — 工具清单、幂等、读回、补偿、凭证代理的执行入口。
- **自治等级** — L0 Observe-only / L1 Recommend / L2 Enforce / L3 Bounded Autonomous / L4 Adaptive；按"环境×工具×操作×数据范围"逐格授予。
- **Guide / Working Memory** — 跨任务稳定领域知识 / 当前任务私有临时状态；分开管理。
- **认知资产** — 可版本化、可测试、可发布撤回的知识件：Claim、核验器、策略包、技能、WorldModel、提示。
- **Evidence Store** — Artifact + 事件库 + 派生索引 + 生命周期（热/温/冷/法律保留/删除队列）。
- **Replay** — 基于事件时间线的离线回放视图：因果时间线、Diff、复现、事故调查。
- **VastaLab** — 隐藏规则/布局/噪声/偏差的可控评测任务集。
- **Evaluation / Release** — 评测记录（任务矩阵、配置、指标、结论）/ 资产发布状态（版本、环境、门禁、灰度、回滚）。

## 4. 功能

*优先级沿用蓝图定义：Must = 完整产品必备；Should = 生产成熟度重要；Could = 生态/高级增强。阶段标注（Stage 1–6）对应蓝图 §31 路线图，Stage 0 为问题验证期不产交付需求。标 ★MVP 的需求属于 §6 MVP 范围并附可测后果。FR-057～059 为蓝图遗留空号，无对应需求，下游不得当作缺漏。[[ASSUMPTION] 阶段标注由蓝图 §31 交付物映射推导，未经逐条用户确认]*

### 4.1 接入与运行时

**描述**：多框架、多模型、多环境的接入层与单机到分布式的运行循环。开发者经 SDK/API/middleware/proxy/sidecar 任一方式接入（FR-002），系统自动探测模型能力（FR-003），Run 全生命周期含暂停/恢复/取消/检查点/预算（FR-004）。realizes UJ-1。

**功能需求：**

- **FR-001**【Must·Stage 1】★MVP — 提供版本化 Model/Environment/Tool/Storage/Verifier 协议。
  - 后果：协议含版本字段；六组消融（FR-064）可在不改动协议的前提下组合启停。
- **FR-002**【Must·Stage 2】— 支持 SDK、HTTP、middleware、proxy、sidecar 五种接入方式（现有轨迹导入为第六种，见 FR-066）。
- **FR-003**【Must·Stage 2】— 自动探测模型视觉/结构化输出/工具/上下文/流式能力。
- **FR-004**【Must·Stage 1】★MVP — Run 支持启动、暂停、恢复、取消、检查点与预算。
  - 后果：恢复时先重新观察真实环境再与检查点比对（不得假设外部世界未变）；预算（动作数/模型调用/时长）超限触发安全停止并导出复现包（对应 AC-08）。
- **FR-005**【Must·Stage 1】★MVP — 支持决策、过渡、终局、重置、外部五类 Observation。
  - 后果：核验器不会把过渡帧或终局帧误判为可行动状态。
- **FR-006**【Must·Stage 2】— 模型路由、超时、重试、熔断、降级与成本记录。
- **FR-007**【Should·Stage 3】— 长任务跨进程/节点恢复。
- **FR-008**【Should·Stage 3】— 定时、事件触发与批量 Run。
- **FR-009**【Could·Stage 5】— 实时流式环境与边缘节点协同。

### 4.2 无损证据平台

**描述**：一切事实的源头。原始观察与工具响应全量入库（FR-010），Artifact 内容寻址且带保留策略（FR-011），派生物永远可回链（FR-012），多维检索（FR-013），图像级回看工具（FR-014），完整数据生命周期含法律保留与可验证删除（FR-017）。realizes UJ-1、UJ-3。

**功能需求：**

- **FR-010**【Must·Stage 1】★MVP — 保存全部关键原始观察与工具原始响应。
  - 后果：写动作 before/after 观察缺失率 = 0（NFR-001）。
- **FR-011**【Must·Stage 1】★MVP — Artifact 具备哈希、来源、类型、大小、时间、分类与保留策略。
  - 后果：任意 Artifact 可按哈希校验取回（对应 AC-03）。
- **FR-012**【Must·Stage 1】★MVP — 派生物可回链源 Artifact、变换与版本。
  - 后果：任意派生结果一键回到原始证据并校验（对应 AC-03）。
- **FR-013**【Must·Stage 1】★MVP — 支持时间、动作、事件、区域、对象、业务实体检索。
  - 后果：任一维度或维度组合的检索返回可跳转 FR-014 回看的证据引用，无死链。
- **FR-014**【Must·Stage 1】★MVP — 图像 inspect、crop、pixel/color read 与并排 Diff。
  - 后果：历史帧按原分辨率恢复；read_pixels 返回指定区域的精确颜色值；Diff 输出同源区域并排对齐。
- **FR-015**【Should·Stage 2】— 视频时间窗、音频片段与多模态对齐。
- **FR-016**【Should·Stage 2】— 按需 OCR、ASR、摘要、状态抽取与 embedding（不默认全量派生）。
- **FR-017**【Must·Stage 3】— 热/温/冷、法律保留、删除请求与删除证明。
  - 后果：删除留下不含内容的证明事件；删除前检查活跃认知/评测/法律保留依赖。
- **FR-018**【Must·Stage 3】— 原始证据权限可独立于派生物与聚合指标。
- **FR-019**【Could·Stage 6】— 证据签名与第三方独立验证。

### 4.3 认知资产与记忆

**描述**：把 Agent 的理解变成可治理的资产。九类认知（FR-020），主张图与全生命周期状态机（FR-021/022），冲突显式化（FR-023），失效传播（FR-024），预算内上下文装配（FR-025）。realizes UJ-1、UJ-2。

**功能需求：**

- **FR-020**【Must·Stage 1】★MVP — 支持 Working、Episodic、Fact、Hypothesis、Counterexample、Guide、Procedure、Preference、Policy 九类认知。
  - 后果：MVP 先交付 Working/Hypothesis/Guide/Counterexample 四类（蓝图 90 天计划）；Policy 只读于 Agent。
- **FR-021**【Must·Stage 1】★MVP — 每条 Claim 含范围、证据、反例、依赖、置信度、版本与状态。
  - 后果：缺证据链路的 Claim 不能进入 accepted 状态。
- **FR-022**【Must·Stage 1】★MVP — 支持创建、修订、晋升、争议、缩小范围、推翻、退役。
  - 后果：被推翻的 Claim 不删除（改失效/缩范围）且保留影响链。
- **FR-023**【Must·Stage 1】★MVP — 互斥主张生成显式 Conflict，不静默覆盖。
  - 后果：同范围互斥主张并存时显式出现 Conflict 记录，检索不静默择一。
- **FR-024**【Must·Stage 1】★MVP — 依赖主张失效时标记受影响 Plan 与资产。
  - 后果：偏差注入测试中旧计划 100% 失效、不继续批量执行（对应 AC-04）。
- **FR-025**【Must·Stage 1】★MVP — Context Builder 按目标、相关性、风险与预算装配上下文。
  - 后果：装配在 token/条目预算内完成且选择依据可追溯；超预算按优先级裁剪不静默截断。
- **FR-026**【Should·Stage 3】— 环境升级后的批量重验证与认知衰减。
- **FR-027**【Must·Stage 5】— 跨 Agent/项目/组织共享需显式发布与权限。
- **FR-028**【Should·Stage 3】— 领域专家审核与批量影响分析（Domain Studio，realizes UJ-2）。
- **FR-029**【Could·Stage 4】— 认知图查询与可视化分析。

### 4.4 可信执行

**描述**：平台的安全核心。所有状态改变型动作执行前形成 ActionContract（FR-030/031），工具清单声明事务语义（FR-032），策略四态（FR-033），参数级批准（FR-034），执行后组合核验（FR-035/036），偏差进入有界恢复（FR-037）。realizes UJ-2。

**功能需求：**

- **FR-030**【Must·Stage 1】★MVP — 所有状态改变型动作执行前形成 ActionContract。
  - 后果：100% 写动作具备 before/contract/policy/execution/after/verification 链（NFR-001，对应 AC-02）。
- **FR-031**【Must·Stage 1】★MVP — 契约含前置条件、预期变化、不变量、成功/失败条件、核验器与超时（幂等键与补偿见 §3 ActionContract 定义，随 FR-038 于 Stage 3 纳入）。
  - 后果：契约缺任一必填段时写动作不执行并留拒因。
- **FR-032**【Must·Stage 1】★MVP — 工具清单声明风险、幂等、读回、补偿、权限与副作用边界。
  - 后果：未声明风险与幂等语义的工具不能被写动作调用。
- **FR-033**【Must·Stage 1】★MVP — 策略结果支持允许、拒绝、请求批准、降级。

- **FR-035**【Must·Stage 1】★MVP — 执行后自动采集观察并运行组合核验器。
  - 后果：核验器组合按契约 verify_with 执行；全部通过才判 pass。
- **FR-036**【Must·Stage 1】★MVP — 核验支持 pass、deviation、inconclusive、system_error；观察不足不得自动归为成功。

## 7. 成功指标

**Primary**

**Secondary**
- **SM-3**：失败 Run 定位首个偏差时间从小时级降至 ≤10 分钟（UJ-1）。验证 FR-060/062。
- **SM-4**：六组消融中 Full 相对 Baseline 的成功率/错误动作净收益为正且稳定（多种子）。验证 FR-064。
- **SM-5**：基础接入 ≤3 工程日、至少 3 个设计伙伴团队每周使用（Stage 2 进入门）。验证 FR-002/081。
- **SM-6**：至少一个客户从 L0/L1 升至 L2 Enforce（由 FR-033 策略逐格授予支撑；FR-039 动态调整为 Stage 5），且试点确认可付费价值（Stage 3 进入门）。验证 FR-033。
- **SM-7**：可靠性指标族——偏差检测 precision/recall、错误认知存活时间、计划失效及时率（Stage 2 起随评测报告跟踪）。验证 FR-035～037、FR-022～024。

**Counter-metrics（不得优化）**
- **SM-C1**：token/存储/端到端延迟成本——不得用无限预算换表面成功率。
- **SM-C2**：误阻断率与不必要审批数——可信执行不得变成审批地狱。
- **SM-C3**：核验 inconclusive 率——不确定不得被静默归为通过。
- **SM-C4**：公开任务与私有变体的过拟合差距——公开基准分数不得成为目标。

## 9. 约束与护栏

**安全**：提示注入防护（观察内容永不自行提升为指令；OCR/网页"指令"只作观察）；Agent 生成代码默认不可信（强沙箱，见 FR-046）；核验优先独立确定性来源，执行模型不做自己的唯一裁判（INV-06，蓝图 §4）；R0–R4 风险分级控制（蓝图 §12.4：R0 只读自动执行 → R4 不可逆默认禁止）；供应链（SBOM、签名、锁定依赖、撤销列表）。**隐私**：字段/区域/Artifact 级敏感分类；传输与静态加密；日志不记模型密钥与原始敏感内容；用户访问/删除请求与删除证明（FR-017/073）；禁止跨客户证据迁移。**成本**：感知变化优先保留变化片段；派生按需触发；同哈希去重；Run/项目/租户三级预算；每阶段测量单位成本。**合规路线**：提供合规所需控制与证据，未审计前不宣称 SOC 2/ISO 认证。
